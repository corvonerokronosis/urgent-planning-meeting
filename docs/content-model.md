# Контентная модель «Срочной планёрки»

Сценарий хранится в `src/data/scenario.ts`, типы — в `src/types/game.ts`. UI не содержит текстов событий и числовых эффектов.

## Событие

Каждый `GameEvent` задаёт:

- `id` — стабильный уникальный идентификатор;
- `stage` — номер этапа рабочего дня; несколько событий с одинаковым номером образуют развилку;
- `time`, `title`, `context`, `thread` — оформление события;
- `when` — необязательное условие появления;
- `messages` — основная цепочка сообщений;
- `messageVariants` — необязательные варианты коротких реплик, стабильно выбираемые из seed прохождения;
- `conditionalMessages` — реплики, зависящие от флагов или шкал;
- `timedDecision` — необязательное кризисное окно с длительностью и безопасным запасным решением;
- `choices` — три варианта решения.

Для каждого этапа должен существовать хотя бы один подходящий по условиям `GameEvent`. Условия альтернатив одного этапа должны быть взаимоисключающими.

## Условия

Поддерживаются пять форм:

- `flag` — наличие или отсутствие флага;
- `stat` — сравнение шкалы через `lt`, `lte`, `gt`, `gte`;
- `relationship` — сравнение доверия конкретного персонажа;
- `all` — должны выполниться все вложенные условия;
- `any` — достаточно одного вложенного условия.

Условие можно поставить на событие, условное сообщение или вариант решения. Недоступному решению следует задать понятный `unavailableReason`.

## Решение

`Choice` содержит:

- `text` и короткую метку `label`;
- немедленные `effects` по шкалам `deadlines`, `budget`, `team`, `client`;
- устанавливаемые `flags`;
- немедленные `reactions` персонажей;
- необязательные `delayedConsequences`;
- `insight` — пояснение для карточки последствия и финального разбора.

Движок дополнительно выводит изменения доверия персонажей из типа решения и явно заданных эффектов. Условный ответ повторно валидируется контроллером, поэтому его нельзя применить обходом интерфейса.

Шкалы автоматически ограничиваются диапазоном 0–100. Нулевые эффекты можно не указывать.

## Отложенное последствие

`DelayedConsequence` задаёт:

- уникальный `id`;
- `afterEvents` — через сколько переходов сработает эффект;
- `effects`, `messages` и необязательные `flags`.

Когда последствие созревает, его сообщения появляются перед основной перепиской нового события, а изменения шкал подсвечиваются в панели состояния.

Сообщение созревшего последствия хранит событие, время и текст исходного решения. В интерфейсе и финальном разборе немедленные и отложенные эффекты показываются раздельно.

## Быстрый режим и кризисы

- Игра запускается с едиными настройками: точные числовые эффекты видны до выбора, испытание и таймер отключены.
- При достижении нуля обычный маршрут блокируется. Игрок выбирает аварийное восстановление с явной ценой или досрочное завершение дня.
- Настройки, seed, минимумы ресурсов, отношения, активный кризис и история решений сохраняются локально в формате `v4`.

## Ветвление без разрастания дерева

В экспресс-сценарии развилка расположена на этапе 5. Оба варианта сходятся на общем финальном событии, поэтому каждое прохождение содержит ровно шесть решений.

## Финалы

Правила шести профилей находятся в `getEnding` внутри `src/game/engine.ts`. Сначала проверяются критические состояния, затем ярко выраженные стратегии и только после них системный или сбалансированный профиль. При добавлении финала нужно также расширить union `Ending['id']` и тесты.

## Чек-лист нового события

1. Уникальные ID события, сообщений, решений и отложенных последствий.
2. Три правдоподобных решения без очевидно «глупого» варианта.
3. Видимая цена каждого решения минимум по одной шкале.
4. Короткая немедленная реакция и конкретный `insight`.
5. Взаимоисключающие условия для альтернатив одного этапа.
6. Проверка `pnpm test` и полное ручное прохождение изменённой ветки.
